Launch a new agent to handle complex, multistep tasks autonomously.

Available agent types and the tools they have access to:
{agents}

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When to use the Task tool:
- When you are instructed to execute custom slash commands. Use the Task tool with the slash command invocation as the entire prompt. The slash command can take arguments. For example: Task(description="Check the file", prompt="/check-file path/to/file.py")

When NOT to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for a specific class definition like "class Foo", use the Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead of the Task tool, to find the match more quickly
- Other tasks that are not related to the agent descriptions above


Usage notes:
1. Launch multiple agents concurrently whenever possible, to maximize performance; to do that, use a single message with multiple tool uses
2. When the agent is done, it will return a single message back to you. The result returned by the agent is not visible to the user. To show the user the result, you should send a text message back to the user with a concise summary of the result. The output includes a task_id you can reuse later to continue the same subagent session.
3. Each agent invocation starts with a fresh context unless you provide task_id to resume the same subagent session (which continues with its previous messages and tool outputs). When starting fresh, your prompt should contain a highly detailed task description for the agent to perform autonomously and you should specify exactly what information the agent should return back to you in its final and only message to you.
4. The agent's outputs should generally be trusted
5. Clearly tell the agent whether you expect it to write code or just to do research (search, file reads, web fetches, etc.), since it is not aware of the user's intent. Tell it how to verify its work if possible (e.g., relevant test commands).
6. If the agent description mentions that it should be used proactively, then you should try your best to use it without the user having to ask for it first. Use your judgement.

Discipline parameters (control sub-agent behavior):

- mode: Execution mode for this sub-agent.
  - "serial" (default): Block until the sub-agent finishes, then continue. Use when you need the result before making your next decision.
  - "concurrent": Start alongside other concurrent tasks in the same turn. All concurrent tasks run in parallel; you receive all results together. Use when you need multiple independent searches or analyses at the same time — e.g., searching three different code areas simultaneously.
  - "background": Spawn the sub-agent and continue immediately without waiting. Retrieve the result later using the background_output tool with the task_id. Use when the sub-agent can work independently and you want to proceed with other work — e.g., running a code search while you continue writing.

- delegation_depth: How many more delegation layers this sub-agent may spawn. 0 (default) means it cannot delegate further (the task tool is denied). 1 means it can spawn one more layer of sub-agents. Use higher values only when the sub-agent truly needs its own helpers.

- permission_override: Dynamic permission overrides for this sub-agent. Keys are tool names (edit, bash, task, etc.), values are ["action", optional path patterns]. Example: { edit: ["allow"], bash: ["deny"], task: ["deny"] }. Overrides are capped by your permissions — the sub-agent cannot gain permissions you lack.

- max_steps: Maximum loop iterations for this sub-agent. Overrides the agent's default. Use to limit long-running agents.

- timeout_seconds: Maximum execution time in seconds (default 300, max 600). On timeout, partial results are saved. Only meaningful for background mode; foreground agents use your own abort mechanism.

- file_scope: Glob patterns restricting the sub-agent's file operations. Only files matching these patterns can be read, edited, or searched. Example: ["src/auth/**", "test/**"]. Use to confine a sub-agent to a specific area of the codebase.

- return_format: Output format discipline.
  - "text" (default): Return the sub-agent's final text output.
  - "structured": Enforce structured output (JSON or well-defined Markdown). The sub-agent receives a prompt instruction requiring parseable output.

When to use concurrent mode:
- When you need to search multiple independent areas simultaneously (e.g., "search A, B, and C in parallel")
- When the research skill instructs you to launch parallel searches
- When no task depends on another's result

When to use background mode:
- When the sub-agent can work independently and you want to continue working
- When you need to retrieve results later via background_output

When NOT to use concurrent or background:
- When you need the result to make your next decision (use serial/default)
- When only one task is needed (serial is simpler and sufficient)
