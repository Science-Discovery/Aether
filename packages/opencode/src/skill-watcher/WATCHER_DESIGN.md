# Skill Watcher 设计文档

Skill Watcher 监听 skills 相关目录的文件系统变更，在文件发生变化时直接清空对应 scope 的内存缓存，使下次 `Skill.available()` 调用能自动从磁盘加载最新内容。

## 设计原则

1. **插件化**：所有新增文件统一放在 `packages/opencode/src/skill-watcher/` 目录下
2. **最小侵入**：旧文件 `Skill` 模块只需新增一个 `invalidateCache(scope)` 导出函数，watcher 单向调用它，不改动其他逻辑
3. **不影响原有流程**：缓存清空操作不阻塞旧逻辑，重建仅在下次 `Skill.available()` 调用时自然触发

---

## 对旧文件的修改

`Skill` 模块的缓存变量（`globalCache` / `projectCache`）是模块内部私有变量，外部无法直接访问。watcher 若要清空缓存，旧模块必须主动暴露一个写入入口，这是唯一合法途径。

```
packages/opencode/src/skill/index.ts    ← 接入点
  └─ 新增一个导出函数（不改动任何已有逻辑）：
       export function invalidateCache(scope: "global" | "project"): void {
         if (scope === "global") globalCache = null
         else projectCache = null
       }
```

```

│                     文件系统（skills 相关目录）                        │
│                                                                     │
│  .aether/skills/  .claude/skills/  .agents/  .opencode/  ...        │
│                              │                                      │
│                     文件发生变更（用户手动编辑）                        │
│                              │                                      │
└──────────────────────────────┼──────────────────────────────────────┘
                               │ FS 事件
                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│              skill-watcher/ 插件（所有新增代码）                       │
│                                                                     │
│  watcher.ts                                                         │
│  ├── 过滤 marked files（skill_manage 正在写入的跳过，防自触发）         │
│  ├── debounce / backpressure（300ms 或 pending ≥ 2000 立即处理）      │
│  └── 按 scope 归类 → 调用 Skill.invalidateCache(scope)               │
│                              │                                      │
│                    直接清空对应 scope 的内存缓存                        │
└──────────────────────────────┼──────────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│                     宿主程序（原有代码）                               │
│                                                                     │
│  Skill.invalidateCache(scope)：cache = null（新增的导出函数）          │

└─────────────────────────────────────────────────────────────────────┘
```

缓存失效由两个时机触发：
1. `shadow-writer.ts` 写入成功后，直接触发 `Skill` 模块缓存失效
2. `watcher.ts` 感知到外部变更（用户手动编辑等），主动触发失效

## 核心机制详解

### 1. 缓存失效策略

FS 事件到达时直接清空对应 scope 的缓存（`cache = null`），无需 dirty flag：

```
FS 事件到达
        │
        ▼
Skill.invalidateCache(scope)：cache = null
        │
        ▼
下次 Skill.available() 调用
        │
        ▼
cache 为 null → 从磁盘读取 → 重建缓存
```

`cache = null` 是幂等操作，连续多次清空与清空一次结果相同；重建只在下次 `available()` 调用时发生，不会因频繁 FS 事件而频繁重建。

### 2. 监听与事件处理流程

```
watcher.ts 初始化
        │
        ▼
┌──────────────────────────────────────────────────────────────┐
│  扫描监听候选目录                                              │
│  global + project paths（向上至 worktree 每层的               │
│  .aether/.opencode/.claude/.agents）                          │
│  即使目录当前不存在也加入候选集（感知目录首次创建）              │
└──────────────────────────┬───────────────────────────────────┘
                           │
               ┌───────────▼───────────────┐
               │  parcel 原生绑定可用？      │
               └───────────┬───────────────┘
                     是 /    \ 否
                    /          \
                   ▼            ▼
           parcel 订阅目录   poll 轮询（每 1500ms）
           （原生 FS 事件）
                   │              │
                   └──────┬───────┘
                          │ fs 事件到达
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  事件进入 pending 集合，同路径去重                              │
└──────────────────────────┬───────────────────────────────────┘
                           │
               ┌───────────▼──────────────────┐
               │  pending.size ≥ 2000？         │
               └───────────┬──────────────────┘
                     否 /    \ 是（事件风暴）
                    /          \
                   ▼            ▼
       debounce 等待 300ms   立即进入批处理（backpressure）
                   │              │
                   └──────┬───────┘
                          │
┌──────────────────────────────────────────────────────────────┐
│  过滤 marked files                                            │
│  skill_manage 正在写入的文件跳过（避免自触发）                  │
│  + 500ms cooling 检查：冷却期内直接返回                        │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  按 scope 归类变更文件                                         │
│  → global / project                                          │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  调用 Skill.invalidateCache(scope)                            │
│  直接 cache = null，下次 Skill.available() 时从磁盘重新加载    │
└──────────────────────────────────────────────────────────────┘
```

### 3. Mark 系统

`skill_manage` 写入文件前后通过 mark 系统通知 watcher 跳过自身产生的 FS 事件，避免形成"写入 → 失效 → 重建 → 再次触发"的循环。

| 时机 | 操作 | 效果 |
|------|------|------|
| 开始写入前 | `markBegin(file)` | watcher 无限跳过该文件 |
| 写入成功后 | `markDone(file)` | TTL = 1500ms 后恢复监听 |
| 写入失败后 | `markDrop(file)` | 立即移除标记，恢复正常监听 |
