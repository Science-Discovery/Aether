# Aether 需求文档

## 1. 项目概述

### 1.1 项目定位

Aether 是一个开源的 AI 研究代理（AI Research Agent）。

### 1.2 核心价值

- **提供商无关（Provider-agnostic）**：支持多种 LLM 提供商，用户可自由选择 Claude、OpenAI、Google、本地模型等任意 AI 提供商
- **完全开源**：100% 开源，社区驱动
- **多界面支持**：提供 CLI/TUI（终端）、Web、桌面应用三种使用方式
- **客户端/服务端架构**：支持本地运行，也支持远程控制
- **可扩展性**：通过插件、技能、MCP 协议等机制实现灵活扩展

### 1.3 目标用户

- 日常使用终端进行开发的软件工程师
- 需要 AI 辅助编程但希望保留对工具链完全控制权的开发者
- 希望在团队中统一 AI 编程工具的技术团队

## 2. 功能需求

### 2.1 AI 对话与 Agent 系统

#### 2.1.1 多 Agent 支持

系统内置多种 Agent，各自具有不同的权限范围和行为模式：

- **Build Agent（构建代理）**：默认代理，拥有完整的文件读写、命令执行权限，用于实际开发工作
- **Plan Agent（规划代理）**：只读代理，默认禁止文件编辑操作，执行 bash 命令前需请求用户许可，适用于代码探索和变更规划
- **General Subagent（通用子代理）**：用于复杂搜索和多步骤任务，可在对话中通过 `@general` 调用
- **Explore Subagent（探索子代理）**：只读子代理，仅具备搜索和读取权限（grep/glob/read/bash/codesearch/webfetch/websearch），专注于快速代码库探索，可通过 `@explore` 调用

用户可通过 Tab 键在 Agent 之间切换。

此外，系统内部还包含以下隐藏代理（用户不直接交互）：
- **Compaction Agent**：负责长对话的自动压缩
- **Title Agent**：自动生成会话标题
- **Summary Agent**：自动生成会话摘要

#### 2.1.2 多轮对话与会话管理

- 支持创建、切换、删除会话
- 会话内保持完整的对话上下文
- 每条消息由多个部分（Part）组成，包括文本、工具调用、工具结果、推理过程等
- 支持流式响应，实时展示 AI 生成内容

#### 2.1.3 会话压缩与归档

- 当对话过长时，自动进行会话压缩（compaction），减少 token 消耗
- 支持会话归档，释放活跃会话列表空间

#### 2.1.4 会话 Fork（分支对话）

- 支持从会话的任意节点创建分支，形成新的独立对话
- 分支会话保留父会话的上下文

#### 2.1.5 会话导入与导出

- 支持将会话导出为文件
- 支持从文件导入会话
- 支持生成会话分享链接

### 2.2 LLM 提供商集成

#### 2.2.1 多提供商支持

支持以下 LLM 提供商（包括但不限于）：

| 类别 | 提供商 |
|------|--------|
| 主流厂商 | Anthropic (Claude)、OpenAI、Google (Gemini) |
| 云服务 | Azure OpenAI、Amazon Bedrock、Google Vertex AI |
| 开源/专业 | Groq、Mistral、Cohere、Cerebras、DeepInfra |
| 聚合平台 | OpenRouter、Together AI、Perplexity |
| 其他 | XAI (Grok)、GitHub Copilot、GitLab |
| 自定义 | 任何兼容 OpenAI API 的自建/私有模型 |

#### 2.2.2 提供商认证

- 支持 API Key 认证
- 支持 OAuth 认证（GitHub Copilot、GitLab 等）
- 认证信息安全持久化存储

#### 2.2.3 模型管理

- 列出可用模型
- 选择和切换当前使用的模型
- 自定义模型参数（temperature、topP 等）
- 按 Agent 配置不同的模型

### 2.3 工具系统

Agent 通过调用工具与代码仓库和外部环境交互。工具分为以下几类：

#### 2.3.1 代码分析工具

| 工具 | 功能 |
|------|------|
| glob | 按文件名模式匹配搜索文件 |
| grep | 按内容正则搜索代码 |
| read | 读取文件内容 |
| ls | 列出目录内容 |
| codesearch | 基于 AST 的语义代码搜索 |
| knowledge | 查询知识库 |
| summarize-dirs | 生成目录结构摘要 |

#### 2.3.2 代码编辑工具

| 工具 | 功能 |
|------|------|
| edit | 对文件进行精确的字符串替换 |
| write | 创建或覆盖写入文件 |
| multiedit | 在单个文件中执行多处编辑 |
| apply_patch | 应用 unified diff 格式的补丁 |
| batch | 批量执行多个编辑操作 |

#### 2.3.3 执行工具

| 工具 | 功能 |
|------|------|
| bash | 执行 Shell 命令 |
| skill | 调用自定义技能 |

#### 2.3.4 Web 工具

| 工具 | 功能 |
|------|------|
| webfetch | 获取并解析网页内容 |
| websearch | 搜索互联网 |

#### 2.3.5 交互工具

| 工具 | 功能 |
|------|------|
| question | 向用户提问以获取信息 |
| task / todo | 创建和管理待办事项列表 |
| plan | 切换至只读规划模式 |
| truncation | 管理上下文窗口 |

#### 2.3.6 LSP 集成

- 通过语言服务器协议（Language Server Protocol）提供代码智能功能
- 支持代码跳转、定义查找等 IDE 级别的功能

#### 2.3.7 MCP 扩展工具

- 支持通过 Model Context Protocol（MCP）接入外部工具服务器
- 支持多种传输方式：HTTP、SSE、Stdio
- 动态发现和注册 MCP 服务器提供的工具
- 支持 MCP 服务器的 OAuth 认证

### 2.4 权限系统

#### 2.4.1 权限控制模型

对 Agent 的每个工具调用实施权限控制，支持三种决策：

- **allow（允许）**：直接执行，无需用户确认
- **deny（拒绝）**：直接拒绝，不执行
- **ask（询问）**：暂停执行，等待用户交互式授权

#### 2.4.2 权限规则层次

- **Agent 级别**：不同 Agent 预设不同的权限规则（如 Plan Agent 默认拒绝写操作）
- **项目级别**：每个项目可独立配置权限规则
- **会话级别**：单个会话中可临时授予或撤销权限

#### 2.4.3 交互式权限授予

- 当工具调用需要用户授权时，在 UI 中展示权限请求
- 用户可选择：允许本次、始终允许、拒绝
- 权限决策可持久化

### 2.5 配置系统

#### 2.5.1 多级配置

配置按优先级从低到高支持三个层级：

1. **系统级**：全局默认配置
2. **用户级**：用户个人偏好（`~/.opencode/opencode.json`）
3. **项目级**：项目特定配置（项目根目录下 `.opencode.json`）

#### 2.5.2 配置项

- Agent 定义与自定义（模型、prompt、权限等）
- MCP Server 配置（本地/远程）
- 插件配置
- LSP 配置
- 自定义指令（custom instructions）
- 快捷键绑定

#### 2.5.3 配置格式

- 使用 JSONC（带注释的 JSON）格式
- 支持 Markdown 文档作为自定义指令来源

### 2.7 项目与工作区管理

#### 2.7.1 多项目支持

- 每个项目对应一个工作目录（worktree）
- 项目拥有独立的名称、图标、颜色等元数据
- 项目维护各自独立的会话列表

#### 2.7.2 工作区

- 项目下可创建多个工作区
- 工作区与 Git 分支关联
- 工作区之间相互隔离

#### 2.7.3 Git 集成

- 自动检测 Git 仓库和分支信息
- 支持从 GitHub PR 拉取代码并启动会话
- 文件变更快照与 diff 生成

#### 2.7.4 快照与回退

- 记录会话中的文件变更快照
- 支持将文件回退到指定消息节点的状态

### 2.8 技能系统（Skills）

#### 2.8.1 技能定义

- 技能通过 Markdown 文件（SKILL.md）定义
- 技能文件描述该技能的功能、触发条件和行为

#### 2.8.2 技能来源

- 项目级技能：存放在项目的 `.claude/skills`、`.agents/skills` 等目录
- 全局技能：用户级别的通用技能

#### 2.8.3 技能调用

- 通过斜杠命令 `/skillname` 在对话中调用
- Agent 可通过 skill 工具主动调用技能

#### 2.8.4 技能发现

- 自动扫描并发现可用技能
- 动态加载和注册

### 2.9 知识库

- 支持创建和管理项目级知识库
- Agent 可通过 knowledge 工具查询知识库
- 在 Web 前端提供知识库管理界面

### 2.10 插件系统

#### 2.10.1 插件加载

- 支持从 NPM 包加载外部插件
- 内置插件：OpenAuth、Codex Auth（GitHub Copilot）、GitLab Auth 等

#### 2.10.2 插件能力

- 提供自定义工具
- 提供 Hook（钩子）
- 提供认证机制
- 扩展 Shell 集成

### 2.11 会话分享

- 支持将会话导出为文件（JSON 格式）
- 支持生成会话分享 URL
- 分享信息包含唯一 ID 和访问密钥

## 3. 非功能需求

### 3.1 跨平台

- 支持 macOS（Apple Silicon 和 Intel）、Windows、Linux
- 通过多种包管理器分发：npm、Homebrew、Scoop、Pacman、Nix 等
- 桌面应用支持三大操作系统

### 3.2 性能

- LLM 响应采用流式传输，实现实时展示
- 事件系统采用批量合并（coalescing），减少 UI 重绘
- 会话压缩机制控制 token 消耗

### 3.3 数据存储

- 本地数据存储使用 SQLite，无需外部数据库依赖
- 遵循 XDG 基础目录规范存放配置和数据文件
- 数据库启动时自动迁移

### 3.4 安全性

- 权限系统确保 Agent 操作可控
- API Key 等敏感信息安全存储
- OAuth token 自动刷新
- 会话分享使用独立密钥

### 3.5 可扩展性

- 通过 MCP 协议接入任意外部工具
- 插件系统支持第三方扩展
- 技能系统支持自定义工作流
- 自定义 Agent 配置

### 3.6 国际化

- README 文档已翻译为 20+ 种语言
- Web 前端支持多语言切换

### 3.7 开发者体验

- 提供 JavaScript SDK 供第三方集成
- OpenAPI 规范描述的 HTTP API
- 完善的文档和贡献指南
