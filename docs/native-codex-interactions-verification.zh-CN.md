## 首次失败与修正

- 新的 queue / interaction 测试进程漏实现完成任务时需要的 `thread/loaded/list`；queue 还缺少连接复用的 `thread/read`。补齐协议响应后相应用例通过。
- 后端首次类型检查发现新的历史 fixture 缺 `updatedAt` 和 `status`，补齐后通过。
- Windows 沙箱拒绝测试进程对自身 `.cmd` 子进程树执行清理，导致 modes 超时清理断言失败。限定同一测试、隔离目录和自身 PID 提权复验后通过；未修改生产清理策略，也未终止用户进程。

交叉审查还修正了队列退出时漏掉后续唤醒、停止前已保存输入被误标可重发、旧停止状态影响新任务、修改草稿绕过待确认请求，以及模式确认前过早保存成功状态的问题。模式变更的保守状态先持久化，再发送；只有合法、对应同一回合的响应才清除可能仍在计划模式的记录。

- 本次未运行真实模型任务，也未启动或重启用户的 Aether 实例；视觉效果和具体 Codex 安装版本仍需手动验收。
- 追加与排队首版仅支持纯文字；图片、文件和阅读选区需在普通空闲输入中发送。

- 未做进程复用性能基准，也不据此声称节省 token 或订阅额度。

## 追加显示与队列入口修正（同日）

用户实测发现，追加后新输出仍挂在原回复下，历史刷新后已显示的前段还会消失。本次只读核查了对应测试回合：原生持久化记录含原问题、追加问题和最后回复，缺少被打断的开头。旧测试仅验证一个原生回合和一个回复，并在刷新前清空展示缓存，没有覆盖这一情形。

修正后，运行中输入默认排队，每条待发消息可“立刻发送”。发送沿用原 ID 并预留队列条目，避免下一轮重复执行；丢失 HTTP 响应时可核对原请求结果。原生执行仍只有一个回合，显示按用户追加消息分段；已开始的工具和文本保留归属，审批记录跟随对应段，用量只保留一份。

同步时检查已有原生条目是否被遗漏、截短或不兼容改写；若有则保留已观察内容并标记部分历史。旧版已删除且 Codex 未存储的开头无法完整恢复；本次未写入或重放用户的测试会话。

本次定向检查包括实时事件与追加、队列转换、历史投影与同步、前端队列交互，以及前后端包级类型检查。覆盖追加前后文本、旧条目迟到完成、审批归属、重复同步不重复显示、停止和发送竞争、同 ID 结果核对。使用本地协议测试进程，未发送真实模型请求，未运行整包测试；当前应用也未被自动重启。

## 异步提问卡片（同日）

本机 Codex `0.164.0-alpha.11.1` 的协议与已有测试会话确认，异步提问通过带 `delivery: "async"` 和 `questions` 的原生消息交付，区别于同步 `item/tool/requestUserInput`。Desktop 的历史中，答案是带原问题条目标识的普通用户输入。Aether 采用现有 `turn/start` / `turn/steer` 发送该关联答案，不声称复用了 Desktop 内部的调用方式。

题目保存为消息上的类型化字段，答案与交付标识使用独立的原子文件记录。界面支持选项和自由回答、已回答状态、同答案核对，后台状态更新不重置草稿。完整与部分历史同步都保留答案记录；只把原生用户消息中的明确回答当作外部回执，不把本地尚未确认的输入当作已送达。

验证采用隔离目录与本地 JSONL 协议进程，覆盖同线程续答、运行中追加、并发和重复提交、失去回执后不重放、派发前失败重试、旧历史重建、外部明确回答、错误线程与超限输入，以及卡片填写和响应顺序。停止会取消尚未派发的回答，删除会话会关闭回答入口并清理交付记录。未运行整包测试、未调用真实模型、未启动或重启用户应用。

首轮前端检查发现同题后台更新会清空草稿，已改为稳定身份与按序复用题目控件，并通过相应用例；迟到的 HTTP 响应也不会覆盖较新的推送状态。审查补上了停止与答案派发的竞态保护。类型检查发现的新增测试类型声明、窄化与递归返回类型问题均已修正。真实账号下从选择到继续生成的交互仍需加载新版前后端后手动验收。
