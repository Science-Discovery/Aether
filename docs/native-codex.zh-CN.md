# Codex 原生智能体

Aether 可以将新会话交给本机 Codex 的 `app-server` 执行。模型调用、工具执行、上下文管理和 Codex 自身的配置由 Codex 负责；Aether 提供对话、文件与 PDF 阅读界面。现有 Aether 引擎和历史会话继续可用。

## 连接与使用

1. 打开 **设置 → 智能体后端**。Codex 默认开启，Aether 自动检查安装、连接、登录和模型状态。已有 Codex 安装且登录可用时，可直接使用，不需要保持 Desktop 窗口打开。
2. 没有安装时，使用页面中的官方安装指引安装 Codex CLI 或 Desktop，再重新检测。只为 Aether 提供引擎时，CLI 即可；当前入口引导用户完成官方安装，不会在后台下载或执行安装脚本。
3. 已安装但未登录时，点击 **使用 ChatGPT 登录**，在浏览器中完成官方授权。浏览器授权不可用时可改用设备码；连接远程 Aether 时默认使用设备码。网页版 ChatGPT 的登录状态不能替代本机 Codex 授权。
4. 登录完成后自动重新检查账户及模型，并刷新同一 Aether 服务在其他项目中的连接状态。看到就绪状态后，新对话选择 **Codex**，再选择该安装提供的模型和推理强度。首次新会话仍默认使用 Aether 后端，已有会话不会被自动切换。
5. 自动发现失败时，可填写 Codex 可执行文件的完整路径并保存。留空恢复自动发现。Windows 会检查 PATH、常见 CLI 位置及 `%LOCALAPPDATA%/OpenAI/Codex/bin/*/codex.exe`；并非所有桌面应用安装方式都提供可供外部启动的入口。

连接的是 Aether 后端所在机器上的 Codex。远程访问 Aether 时，浏览器本机安装的 Codex 不会自动成为远端的后端。设置中的路径只从 Aether 的全局配置读取；项目目录内的同名配置不能指定待执行的程序。

Codex 的全局设置保存在服务端全局配置目录的 `aether.integrations.jsonc`（默认 `~/.config/aether/`），避免旧版桌面端因不认识 `native` 字段而启动失败。本分支仍能读取主配置中已有的 `native`，独立文件中的设置优先；保存设置时仅将正在使用的主配置里的 `native` 迁出。共享文件中已有的 `latex` 会原样保留，但本分支不读取其设置、不解析其中的环境变量或文件占位符，也不提供 LaTeX 功能。此机制需要更新后端程序，只有前端热更新不会改变旧后端的保存方式。

若旧混合版本尚未完成迁移，主配置文件中仍含 `latex` 等本分支不支持的字段，配置校验会拒绝加载，本分支不会自动删除这些字段。切换前应先在混合版本中保存设置完成迁移，或备份后将对应字段移入共享配置文件。

不需要把 Codex 登录令牌粘贴到 Aether。登录通过 Codex 的 `account/login/start` 发起，凭据的保存和刷新仍由 Codex 管理；Aether 只临时持有登录链接、设备码和尝试状态，不读取或复制认证文件。登录进程在成功、取消、失败或十分钟到期后释放。关闭登录界面会取消尚未完成的尝试；网络响应丢失时先核对原尝试，不自动发起另一次登录。

连接检测执行握手、账户状态、模型目录查询，并在隔离目录导出协议 schema 检查自动审批、追加指令和计划模式能力，不发送推理任务。检测显示需要登录时，可通过设置页授权；若 Codex 仍报告已有账户但调用失败，可在 Codex 中重新登录后刷新状态。设备码若被账户或工作区策略禁用，需按官方指引启用或改用可用的浏览器登录方式。

关闭 Codex 后不再自动探测，也不能创建 Codex 会话或发送新消息；已有历史仍可查看，Aether 会话照常使用。正在执行的 Codex 任务可完成，结束后释放进程。开关、路径和保留数量都只读取全局配置。修改这些设置不重置正在运行的会话。

模型目录在后台加载，切换引擎不等待检测完成。服务端合并并发检测，成功结果缓存 60 秒，失败结果缓存 5 秒；手动检查可刷新缓存。首次检测尚未完成时会显示状态，并在可用模型确认后开放发送。

同一服务器和路径已有可用模型目录时，缓存过期或后台查询的临时网络错误不会单独阻止发送，实际派发仍由后端校验配置与模型。明确返回关闭、未连接、登录失效、检测错误或模型不可用时，界面仍会阻止发送。旧版连接接口未提供 `enabled` 字段时按默认开启处理；新开关及进程复用功能仍需要相应版本的后端，前端热更新不会更新正在运行的桌面后端程序。

## 会话与科研上下文

会话创建后固定使用所选引擎，避免切换后上下文含义发生变化。Codex 的线程 ID、模型和推理强度保存在会话元数据中，后续消息恢复同一个原生线程。恢复失败会显示错误，不会悄悄创建空白线程。

左侧在每个项目或工作区内按 **Aether、Codex** 分组，再列出各自的会话；旧会话归入 Aether。Codex 分叉独立列出，普通 Aether 子会话继续跟随根会话，归档、未读状态和批量选择保留。分组针对当前已加载的列表，加载更多会继续补充对应组，不代表已经列出全部历史。分类本身不会授予跨会话读取等额外工具能力。

未立即要求回复的论文上下文会保留到实际派发时。连接或模型检查失败不会消费这些待发送内容；已经显示失败的普通消息需要用户重新发送。任务派发后若连接中断、执行结果不明，Aether 不自动重放输入，以免重复执行文件或命令操作。

单次原生请求的传输上限为 8 MiB。待发送上下文会在保存前预检，并预留 1 MiB 给后续问题和请求元数据；超限的新上下文不会入库。普通输入过大而未发送时，也不会消费此前排队的上下文，可以缩短问题后重试。

文本、工作区文件、图片和 PDF 上下文可传递给 Codex。上传的 PDF 会提取带页码的文本；扫描件可能没有可提取文字。模型明确声明不支持图片时，Aether 会提前拒绝；旧版本未提供能力信息时，由 Codex 校验。PDF 选中内容、提问、翻译与初读继续使用 Aether 阅读界面，并走会话所选引擎。

Codex 回复、工具状态、思考摘要和用量映射到 Aether 的会话事件中。工具执行由 Codex 负责，Aether 不再运行自己的智能体循环。显示的思考内容取决于 Codex 实际提供的摘要。用量展示根线程报告的数据，不会把子线程事件覆盖到根线程统计中，也不估算未提供的费用。

完成的原生 `imageView`、`imageGeneration` 条目可直接显示图片并点击放大，重新打开或刷新历史后也可展示。图片通过已保存的会话、消息和工具条目读取，不接受浏览器自行指定文件路径；支持项目目录内的 PNG、JPEG、GIF、WebP 文件，以及生成条目中的内嵌图片数据，单张最大 16 MiB。文件不存在、位于项目外、仅提供原生文件 ID 或格式不支持时保留工具记录并提供重试入口；这不等于支持任意 Markdown 本地图片路径。

## 斜杠命令与原生技能

Codex 模式下，在输入框开头输入 `/` 可搜索本模式的快捷操作与可用技能。`/new` 新建 Codex 对话；`/model` 选择原生模型；`/plan` 选择执行或计划模式；`/permissions` 选择审批权限；已有会话中的 `/status` 打开上下文与账户额度面板。模型、模式和权限沿用输入框原有配置，从下一轮生效；具体选项取决于本机连接状态及版本能力。

`/skills` 打开原生技能列表，可按名称、说明搜索，并手动刷新；也可直接在 `/` 菜单中搜索技能名称。技能从当前项目目录对应的 Codex `skills/list` 读取，只展示其报告为启用且可用的技能。未安装、旧版本不支持、读取失败和技能配置错误会在技能列表中说明。界面保留已加载的列表，手动刷新会重新扫描；实际发送前仍会重新验证所选技能。

选中技能后以 `$技能名` 标签保存在草稿中，名称和路径一起保存；同名技能可通过来源路径区分。普通发送、排队及“立刻发送”都携带相同的技能引用。实际发送前，后端在执行连接上重新检查技能仍可用，再按[官方 App Server 的技能调用方式](https://learn.chatgpt.com/docs/app-server#skills)附加 `skill` 输入项；Codex 负责加载技能内容。已禁用、删除或不属于当前项目的引用会拒绝发送，不以名称猜测其他技能。

技能标签随草稿、输入历史及可恢复的消息编辑保留。含 Codex 技能标签的草稿切到 Aether 模式时，发送会提示切回 Codex，草稿仍保留。Aether 模式继续使用自己的命令、技能及 MCP 入口。这里提供的是 Aether 已接通功能的快捷入口，不包含 Desktop 的全部专属命令。

通过 SDK 使用 `noReply` 暂存研究上下文时不能附加显式技能引用；技能应随实际问题发送。该组合会在保存上下文前被拒绝，避免失效技能一直留在待发上下文中阻止后续对话。

## 审批与停止

输入框中的 **Codex 权限** 按会话保存，从下一轮生效；不修改 Codex 全局配置，也不替用户回答当前已弹出的审批请求。

| 选项     | 实际行为                                                                                     |
| -------- | -------------------------------------------------------------------------------------------- |
| 请求批准 | 工作区写入沙箱；需要批准时交给用户处理。                                                     |
| 帮我批准 | 同样使用工作区沙箱，由 Codex 原生 `auto_review` 审查；可能批准、拒绝或超时。新会话默认此项。 |
| 完全访问 | 关闭 Codex 沙箱与审批提示，允许访问文件与网络。                                              |

旧会话没有保存权限时仍按“请求批准”执行。自动审批需要本机 Codex 在创建、恢复线程及每轮执行参数中明确支持；不支持或探测失败会提示错误，不能静默冒充自动审查。对话中展示收到的自动审查结果；没有返回结果的审查会标记未完成。界面选择本身不是某个操作获批的证据。

Codex 请求命令执行、文件修改或额外权限时，Aether 显示问题卡片并将选择返回 Codex。文件修改会展示原生差异；缺少可审阅差异或请求过大时会明确拒绝。Aether 原有的自动授权开关不会代替这些审批。不支持的请求会明确拒绝；不会自行扩大权限。需要输入秘密信息的问题应在 Codex 中处理。Codex 撤回请求后，对应问题卡片也会取消。

同一会话在安全完成一轮后保留独占的 `app-server` 连接，下一轮继续使用原线程和进程；新进程只初始化一次。服务端默认最多保留 **4 个空闲进程**，设置中可调整为 **0–16**；0 表示每轮完成后回收。空闲超过 **30 分钟**或超出数量时回收最久未用的进程，正在执行的任务不参与空闲数量淘汰。回收后再次发送会启动新进程并恢复持久化线程。删除会话、实例释放、停止或异常会关闭对应进程；关闭 Codex 或修改路径会回收空闲连接，并让运行中的连接在本轮完成后退出。

主线程结束后会继续等待经父子关系验证的原生子任务；子任务输出带来源标记，审批仍由用户处理。无法确认子任务完成时会保留运行状态或报告错误，不会以静默超时冒充成功。停止会中断已确认的活跃任务、清理待答问题并关闭进程；清理完成前不能开始同一会话的新一轮。进程被回收后，临时审批状态仍可能丢失并再次询问。

原生线程、App Server 进程与服务端提示缓存是三个不同层次：旧实现也会恢复同一线程，并未每轮新建对话；保留进程主要减少启动、握手和恢复开销，不能保证额度节省。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)描述了持续连接上的多轮会话与线程卸载；这里的进程池是 Aether 自己的资源管理策略，不代表复制了 Desktop 的内部策略。[提示缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)说明缓存依赖前缀匹配等服务端条件，不能仅凭本地进程重启断言缓存失效，也不能将 API 缓存计费规则直接当作 ChatGPT 订阅额度规则。Aether 保留 Codex 返回的缓存用量，不自行估算节省比例。

## 异步提问卡片

Codex 根线程通过 `request_user_input_async` 发出的结构化问题会显示在对应回复中。每题可选择一个选项或填写自由答案；全部填写后点击提交。异步问题与命令权限审批分开，模型发出问题后可以继续执行，不会因为卡片尚未回答而自动进入同步审批的等待状态。

输入框上方会提示尚未提交的提问题组，点击可跳到原卡片。提示读取服务端已保存的整段会话，不只统计浏览器当前加载的消息；已提交、送达待核对或已回答的卡片不计入待答数量。外部客户端新问题仍需先同步到 Aether 才会出现。

“忽略当前提醒”只隐藏点击时当前会话已有的待答提醒，不提交答案、不修改原卡片。忽略记录按服务端、项目目录、会话和原生问题身份保存在当前客户端，刷新或切换会话后仍生效；之后新增的问题照常提示。仍可在历史卡片中回答已忽略的问题。

卡片里的“跳过这组问题”会向 Codex 明确表达每题都不提供回答，不会发送尚未提交的草稿，也不代表同意或批准任何操作。交付确认后显示“已跳过”；失败或结果不明时，卡片保留重试或核对入口，使用同一份已保存决定，避免重复发送。

跳过是 Aether 的交互约定，不是对 Desktop 内部 Skip 行为的完全复刻。本机 Desktop 的异步 Skip 主要记录客户端状态，未提供可直接复用的专用跳过 RPC；Aether 沿用已有回答封装发送明确的“不回答”文字，并保存自己的跳过标记。原生历史里的确切自有“不回答”文字也可恢复该标记，不能据此推断 Desktop 中仅在界面上跳过的问题。

答案关联原线程、问题条目和题目序号。Aether 持有可追加的活跃回合时，使用原生追加接口交付；回合已结束时，在同一线程开启新一轮。启动、停止收尾或其他不可追加状态会提示稍后再提交。不会将旧问题的答案交给另一条原生线程。

题目随消息保存，答案及交付标识另行持久化。刷新、重复事件和同答案重试不会再次派发；结果不明时只核对已有记录，不自动重发。明确在派发前失败的回答可重试。已提交的回答不能原地改写，要更正时发送新的普通消息。已回答表示答案已交付，不表示后续任务已经完成。同步到 Desktop 明确保存的对应回答后，也会标记已回答。

历史刷新可恢复原生历史中带结构化字段的旧问题；没有问题字段的普通文字列表不会被猜测成卡片。本次运行中观察到的原生子任务问题在子任务面板中单独回答，不计入根线程的提问提醒。异步提问不是秘密信息输入通道。

## 子任务

已有 Codex 会话中的 `/tasks` 打开子任务面板。Aether 观察到子任务后，输入框上方也会出现简洁的子任务入口及待答数量。面板显示各任务的运行状态、最近结果，以及结构化异步提问；可以选择选项、填写答案或跳过问题。子任务记录独立保存，刷新根线程历史不会丢失这些记录，回退移除的轮次所产生的任务也不会继续混入当前列表。

答案始终交给提问的子线程。父任务仍持有执行连接时，通过该连接在子线程中追加或继续；父任务结束后，先验证原生父子关系，再将子线程关联为自己的 Aether 会话并继续。回答结果不明时保留原交付标识，不自动重复派发。关联子会话仍在运行时，父会话暂不开始下一轮，以免两个 Aether 连接同时接管同一子线程。

任务空闲后可点击“打开子任务”阅读完整记录并独立继续讨论。这里显示的是 Aether 运行时观察到的任务及已关联子会话状态，不是 Desktop 全部子任务的实时监视器；服务重启后不能确认的运行状态显示为未确认，不猜测已经完成。

## 追加指令、排队与计划模式

Codex 运行中，输入框继续发送的消息默认 **排到下一轮**，当前任务成功结束后按顺序执行。停止按钮单独保留，不再提供发送方式下拉选项。排队时记住模型与推理强度；权限和计划模式采用实际开始下一轮时的会话设置。

确认队列已空时，清除“已加入队列”的成功提示；失败及送达结果待核对的提示仍保留。

每条待发消息可点击 **立刻发送**，通过原生 `turn/steer` 补充到当前回合。只有 Aether 当前持有执行连接且本机 Codex 支持该能力时开放；它不能接管 Desktop 中正在执行的回合。发送沿用同一消息标识，并与自动出队互斥，已追加的消息不会在下一轮再发一次。如果该回合已经结束，界面会保留条目并提示核对或继续队列，不会悄悄改成新任务。

追加前后的输出分别显示在对应用户消息下，底层仍是同一个 Codex 回合。已经开始的文本或工具条目继续归属原显示段；累计用量只记录一次。历史刷新发现原生记录漏掉已显示片段或截短内容时，会标记部分同步并保留本地观察记录。旧版已删除且原生历史也没有保存的片段无法自动重建。

运行中排队和队列中的“立刻发送”支持文字、图片、文件引用、论文截图及选区提问，沿用普通发送的上下文构建和原生附件转换。排队时保存完整输入，尚不加入模型历史；队列列表仅展示文字摘要和附件名，不反复传输附件内容。提交失败保留草稿，提交期间继续输入或切换会话不会被迟到的确认清空。

排队响应丢失时，“重试原消息”使用原消息标识、附件字节和模型设置核对或重交原请求，不重新生成阅读模式的 PDF，也不清除当前编辑框里的草稿。修改内容不能绕过上一条待确认请求；放弃重试后再发前仍应核对历史，避免重复输入。

待发队列最多 20 条，文字摘要最多 65536 个字符。单条序列化输入最多 32 MiB，其中上传附件合计最多 20 MiB；整个队列最多 64 MiB。实际派发仍受原生请求的 8 MiB 传输上限约束。超限会报错；尚未发送的条目可移除。工作区文件保留路径，按派发时的文件内容读取；选区文字和上传附件保存提交时的内容。

队列独立持久化，不提前加入模型可见历史。任务失败、用户停止或服务重启后暂停，需要检查条目并点击继续。无法确认是否已经送达的输入不会自动重放；失败或结果不明的队列条目需要先核对历史并移除，再继续剩余条目。点击“立刻发送”后若网络失败，可通过 **核对发送结果** 使用原消息及回合标识确认，避免重复派发。取消过程中已经保存但未完成派发的输入会保留失败记录，而不会伪装成可直接重发的待发消息。

输入区显示启动、运行、等待用户和停止中的状态。状态描述的是 Aether 当前持有的连接，并非跨客户端的全局执行状态。

**执行 / 计划** 调用 Codex 原生协作模式（`default` / `plan`），沿用该版本提供的模式指令。选项按会话保存，切换从下一轮生效；它与审批权限分开，计划模式不是文件访问权限开关。旧版本不支持时继续提供普通执行模式，并说明计划模式不可用；不能确认已处于计划模式的线程能够切回普通模式时，发送会明确报错。

## 上下文与账户额度

上下文占用按 Codex 最近报告的输入 token 与上下文窗口计算，不用整段对话累计 token 猜测。保留原生返回的输入、输出、缓存及总 token；不把推理 token 再加进已经包含它的总数。原生线程没有报告窗口或用量时显示未知，费用也不会显示为推算出的金额。

分叉保留所继承轮次中已经观察到的模型和用量记录。旧分叉刷新历史时，会按原生来源与轮次内容核验后补回遗漏的统计；这些是继承历史的读数，不代表分叉又产生了一次消耗。没有真实证据时仍显示未知，已知的提供商、模型和最后活动时间不会因为缺少 token 统计而一并消失。

会话上下文面板可查看 Codex 返回的账户额度与重置时间，支持手动刷新。读取使用独立的短时连接，只调用账户额度接口，不运行推理；成功结果缓存 60 秒，不可用结果缓存 5 秒。额度属于登录账户，并非本会话独享；缺失或不支持的数据明确显示不可用。

## 原生历史刷新

打开已有 Codex 会话、Aether 中一轮生成完成后，或切回空闲会话所在的 Aether 窗口时，界面会异步读取原生线程历史；也可点击 **刷新 Codex 历史**。自动刷新合并十秒内的重复读取，手动刷新绕过该缓存。普通消息接口、搜索及导出读取最近一次展示缓存，不会自行拉取全部原生历史。

读取使用独立的短时 `app-server` 连接，通过 `thread/read`、`thread/turns/list` 和必要的 `thread/items/list` 分页取数，不恢复线程、不发送模型请求。其他客户端已保存的完整回合可以导入 Aether；重复刷新不会新增相同消息。它不是 Desktop 的逐字实时同步；写入操作的原生归属检查与主动释放见下节，审批仍须在发起任务的客户端处理。

原生完整历史是 AI 内容的来源。Aether 独立保存待发输入、交付账本、引用与附件关联、原回复标识及收到的用量和自动审查记录；消息表只是展示投影。普通发送不再从这张缓存表推断哪些输入尚未交付。数据库事务保证账本和缓存更新一起提交或回滚；旧会话的发送游标无法解释时会停止迁移并保留原记录，不猜测重发。

读取最多处理 100 页、10000 个 item、32 MiB 数据，设置超时。遇到接口不支持、未知内容、未完成回合或分页异常时，保留旧记录和同步诊断；“部分历史”状态不在对话栏或刷新按钮提示中展示，历史不可用时仍提示检查连接后重试。新发现的未知条目以原始信息显示。部分读取追加的内容不能保证完整原生顺序，完整读取后再统一排列。

发现外部回退造成已知轮次消失或新增压缩标记时，会再次完整读取并比对线程状态、时间和全部轮次。历史一致、具有已完成边界且没有未确认交付或正在提交的回答时，才更新展示记录及交付账本，并释放可能持有旧上下文的空闲连接。被回退的输入保留内部交付凭据，旧请求标识不能再次发送；待发送队列、失败输入和编辑草稿保留。末尾仍为中断状态、读取发生变化或无法完整解释时继续保留旧记录。两次一致读取不是跨客户端互斥锁，仍应避免双端同时操作。

上下文压缩不等于删除聊天记录：Codex 仍保留的正文继续展示，独立压缩条目附在前一条回复中，不生成虚构的问题或改变原回复的分叉位置。缺少压缩后用量报告时，不估算新的占用量。被移除问题的待答提醒随历史清除；若回退只移除了答案、保留了问题，该卡片会恢复可回答状态。

外部历史若缺少逐轮模型或用量，Aether 不根据当前默认模型猜测，也不把占位的零值当成真实零消耗。本地图片路径可保留，但浏览器未必能展示外部客户端的 `file://` 图片；图片文件 ID、未完整展开的原生子任务等会标记部分同步。历史中的 Aether 引用保留原消息标识。

删除 Aether 会话不删除 Codex 原生线程。已绑定原生线程的会话，其 Aether 上传附件和阅读文件会保留，避免 Desktop 后续读取失效；这些保留资源暂未提供自动清理流程。

## 接入已有 Codex 会话

在 Codex 模式输入 `/resume`，可搜索并接入当前项目目录下已保存的 Codex 会话，包括在 CLI、VS Code 或 Desktop 中创建的普通对话。接入仅建立 Aether 与原生线程的关联并读取历史，不复制出另一个原生线程，不发送模型请求；已经关联的会话会直接打开。已有会话的原生模型信息可能不完整，此时仍保留未知状态。

列表通过 `thread/list` 的 `useStateDbOnly` 选项读取 Codex 已建立索引的会话，避免每次打开都扫描并修复磁盘上的全部历史文件。尚未进入原生索引的旧记录可能不会出现在此列表；选择接入时仍重新读取完整历史并核验会话状态。

目录必须与当前 Aether 项目匹配。正在运行、临时未保存、已归档、带未完成持续目标或历史无法完整读取的会话暂不接入。列表分页与搜索结果绑定本次 Codex 配置，切换服务端或项目后旧响应不会继续导航。接入后两端仍共享同一个原生线程，应避免同时发送、审批或回退；此功能不是聊天备份导入或跨客户端执行锁。

## 在客户端之间继续会话

读取历史不取得执行权。已验证的 Codex 0.164.0-alpha.11.1 在 `thread/resume` 时通过原生写入锁拒绝另一个执行进程；独立读取返回 `notLoaded` 不表示其他客户端空闲。Aether 在恢复发送、回退、压缩和分叉来源时使用原生恢复检查；检测到被其他客户端占用时停止操作，不强行抢占或将同一消息另开线程发送。分叉必须先取得来源线程的执行权，因为原生 `thread/fork` 本身可以在来源仍被写入时成功。

Aether 保持现有空闲进程复用。需要切换到 Desktop 或其他客户端时，可在空闲会话输入 `/release`，选择“释放连接”。此操作关闭 Aether 持有的该会话进程，保留原生历史和 Aether 记录；进程内终端与工具状态结束。任务、持续目标、子任务、待答问题、待发队列或未确认的提交尚未处理时拒绝释放。再次在 Aether 发送时恢复同一原生线程。释放不会打开其他客户端，也不会替另一个客户端终止任务。

如果会话已由 Desktop 持有，应在 Desktop 结束任务并释放其持有的会话连接后，再回 Aether 操作。两端的审批和交互请求绑定各自的原始连接，Aether 不转发 Desktop 的待批请求。此实现不依赖 Desktop 的私有协调协议，也不承诺跨客户端逐字同步、抢占执行或在所有历史 Codex 版本上具有相同锁语义。

## 手动压缩上下文

已有 Codex 会话中的 `/compact` 打开压缩面板，点击“开始压缩”后调用原生 `thread/compact/start`。压缩使用 Codex 额度；不会删除仍被 Codex 保留的聊天正文，也不会撤销工作区文件。Aether 等待实际压缩完成后同步历史及原生用量，不把接口接收成功当作压缩完成，也不估算缺失的压缩后用量。

压缩与同一会话的发送、分叉和回退互斥，需要先结束当前任务、处理待发队列与未确认交付。可用原有停止入口取消 Aether 正在执行的压缩；结果只有在确认后才解除保护。网络响应丢失时，重新打开面板可用“检查结果”核对同一请求，未确认的请求不会自动重新压缩；尚未送达的原请求可通过“重试同一请求”继续核对或提交。服务意外退出且无法证明结果时保留未决状态，不以超时推断失败。

## Aether 科研工具

本机 Codex 的协议明确支持动态工具时，Aether 在**新建原生线程**时注册以下只读工具，模型可按任务需要调用：

| 工具                          | 可读取的内容                                           |
| ----------------------------- | ------------------------------------------------------ |
| `aether_knowledge_search`     | 当前会话明确选择的知识库，返回文件、页码与相关片段     |
| `aether_pdf_annotations_read` | 当前项目目录内 PDF 的已保存选区、批注及页码            |
| `aether_session_search`       | 当前项目目录下 Aether 已保存会话的标题与正文匹配       |
| `aether_session_read`         | 指定会话最近的用户与助手正文，不包含隐藏推理和工具输出 |

新会话输入框中的知识库按钮用于选择资料；先选择后发送，运行中排队的消息沿用当前会话选择。未选择时知识库工具返回未配置，不回退到全局知识库或向上查找目录。知识库查询使用用户配置的嵌入服务；查询与结果有数量、长度和时间限制，停止信号会传递给支持取消的请求。读取 PDF 批注不会迁移或改写批注文件。

跨会话工具读取 Aether 最近保存的展示记录，可能落后于其他客户端或正在运行的会话，不会自动读取其他项目或全部 Desktop 历史。工具返回的论文、批注及聊天内容是资料，不是新的执行指令。

官方接口目前只允许在线程创建时注册这些动态工具。已经存在或通过 `/resume` 关联的旧线程不会被重建或注入工具；原生分叉是否继承动态工具尚无本版可验证的接口证据，因此分叉也不显示已注册标记或知识库选择入口。要使用本套工具，应新建一个 Aether Codex 会话。Aether 的旧工具覆盖、技能演化和整套自有智能体循环不因此进入 Codex 执行链路。

| 功能     | 操作与预期                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| MCP      | 输入 `/mcp`，核对服务与工具，点击刷新；未配置时应为空，错误或缺少连接状态时不显示为已连接                                          |

## 分叉与编辑重发

Codex 会话支持 AI 回复下方的分叉，以及用户问题下方的“回退到此处并编辑”。分叉保留所选回复所在的完整原生轮次及此前历史，原会话保持不变；编辑则在确认后回退当前会话，把原问题及可恢复的附件放回当前草稿，由用户修改后手动发送，不新建分叉。

Codex 分叉在项目的 Codex 分组中独立列出，页面顶部不再显示来源会话链接；归档或删除来源不会连带处理这些分叉。底层保留来源关系：新分叉记录直接来源，旧分叉沿用此前保存的来源关系，可能指向更早的祖先会话。统计补回以 Codex 的原生来源记录为准，不猜测旧关系。兼容旧记录不改写用户数据库，也不影响普通 Aether 会话树及真正的智能体子任务。进入新分叉时展开最后继承的回复，避免将折叠内容误认为缺失。

开启会话树显示时，Codex 会话仍可在侧栏展开自身的消息导航，以单条直线按消息顺序排列，点击记录跳转到当前会话中的对应位置。这里包含该会话继承的历史和后续消息，包括中断或尚未回复的问题；不会把来源、其他分叉或子任务的消息合入同一条线。真正的智能体子任务仍作为子会话显示，普通 Aether 会话继续使用原来的分支树。

普通文字及工作区文件引用可恢复为草稿。图片、上传附件或复杂阅读上下文等无法在刷新后完整恢复的消息，暂不允许原地回退编辑；会保留原历史并提示使用“从这里继续”，先保留完整轮次，再发送补充问题。

分叉由 Codex `thread/fork` 执行，再读取新线程历史生成展示记录；继承项目目录、模型、推理强度、权限及协作模式。分叉聊天不会复制工作区或撤销已有文件修改。保留范围内的历史须完整可读，已结束的中断或失败轮次不再导致整段历史被拒绝；新线程须保留相同轮次顺序、状态和条目内容。切点之后的局部不支持条目不会阻止较早位置的分叉，但分页不完整、读取期间变化等全局问题仍会拒绝。执行中，或运行中追加消息造成无法精确截断时也会拒绝，只允许原生轮次边界。带未完成持续目标的线程、缺少安全分叉能力的 Codex 版本不会自动启动目标或改写原线程。

新分叉首次导入可保留已结束轮次中的部分输出及未完成工具原始记录，不把它们当作成功执行。普通跨客户端历史同步仍保守处理未完成轮次，不能凭另一个进程读取到的中断状态认定外部任务已停止。

原生分叉结果无法确认时不自动重试；Codex 中可能已产生未关联的新线程，原会话仍然保留。

编辑使用 Codex `thread/revert`，移除所选问题所在轮次及之后的历史，保留同一个原生线程。它不会撤销已经修改的工作区文件，也没有 Aether 通用回退的撤销恢复功能；需要保留另一条讨论路线时应先使用分叉。确认前会检查已有草稿、附件能否恢复及原生历史边界，确认后先保存原问题草稿，再请求回退。运行中的任务、非空消息队列、未确认的输入交付及未完成持续目标须先处理。

回退按完整原生轮次进行，不能从同一轮中途的“立刻发送”消息开始编辑。Aether 会在确认时再次检查历史未发生变化，验证原生回退结果后一起更新本地展示与交付记录。断线导致结果不明时暂时阻止继续发送，可点击“核对回退结果”；核对使用原操作标识，不重复执行回退。普通 Aether 会话仍使用原来的回退流程。

## 当前边界

输入 `/mcp` 可查看当前项目 Codex 配置中报告的 MCP 服务、认证状态、工具说明和错误，并手动刷新。已有会话存在匹配的 Aether 执行连接时，使用该连接按原生线程查询，并注明为当前会话状态；否则使用独立的短时连接并注明查询范围。查询不恢复线程、不启动模型，也不代表 Desktop 窗口的实时状态。服务目录按官方接口分页读取，异常或不完整读取不会显示为成功的空目录。

认证字段以界面语言显示：`bearerToken` 为令牌认证，`oAuth` 为已通过 OAuth 登录，`notLoggedIn` 为未登录，`unsupported` 为服务未提供认证支持。认证字段不代表工具调用成功；缺少连接状态时也不推断已经连接或连接失败。

支持 OAuth 的已配置服务会显示登录入口。Aether 调用原生 `mcpServer/oauth/login`，用户主动打开返回的授权页面，收到匹配的 `mcpServer/oauthLogin/completed` 后才显示完成。凭据由 Codex 保存，Aether 不读取或复制令牌。取消只关闭该次登录连接；丢失响应时沿用原请求标识核对，不另开登录。同一时刻只允许一个 OAuth 流程。成功后向该项目、该 Codex home 的已有执行连接发送 `config/mcpServer/reload`，由 Codex 安排工具连接刷新，不结束进程或任务。旧版本不支持或刷新失败时仍保留连接，并在授权完成卡片中提示任务结束后可使用 `/release` 再继续；收到刷新响应不等于所有工具已经连接成功。

工具发起标准 `mcpServer/elicitation/request` 时，Aether 在输入框上方显示临时表单或授权网址。表单支持有约束的文字、数值、布尔、单选和多选；可提交、拒绝或取消。打开网址不会自动确认，需单独提交完成操作。请求和答案不写入聊天数据库；停止、断线、原生撤回或 15 分钟超时后失效，旧卡片不能提交到新任务。支持当前执行根线程及已验证子线程，不接管 Desktop 的请求。嵌套结构、密码字段、`openai/form` 扩展及设备验证尚未支持，不声明这些扩展能力。

- 这是 Codex 引擎接入，不是控制已有 Codex Desktop 窗口，也不承诺复现 Desktop 独有的界面、插件或当前打开的会话。
- 使用 Codex 自己的工具与配置；新线程可额外使用上述四个 Aether 科研工具，技能演化、旧工具覆盖及旧斜杠命令不接入原生线程。
- 原生会话支持手动压缩、在轮次边界回退并编辑问题，暂不支持任意修改/删除单条历史和 shell 模式。回退需要本机 Codex 支持 `thread/revert`，不支持的旧版本或旧式原生历史会明确报错，不改用本地隐藏消息模拟回退。
- 原生会话可导出记录，但暂不支持从 Aether 备份恢复为可执行的原生线程。导出的记录不能代替 Codex 自己的线程存储。
- 此阶段仅支持 Codex，其他原生引擎和 Overleaf 不在本次实现中。

## 维护与验证

协议处理位于 `packages/opencode/src/native/`，安装诊断接口为 `GET /native/codex`，历史刷新接口为 `POST /native/codex/:sessionID/history`。会话的可空 `engine` 列兼容旧数据库；没有该字段的会话仍使用原引擎。新增 `native_state`、`native_input`、`native_dispatch` 保存迁移状态、输入和交付证据，并兼容旧数据库已登记但未实际运行新迁移的情况。

`packages/opencode/test/native/` 覆盖真实子进程 JSONL 通信、异常退出、进程树清理、线程恢复、审批与提问、中断竞态、附件和 PDF 提取、旧库升级及阅读会话引擎隔离。前端测试覆盖安装设置、模型选择与发送流程。测试使用独立数据目录，不依赖用户真实账户。

运行控制接口为 `GET /native/codex/:sessionID/runtime`、`POST /native/codex/:sessionID/steer` 及 `/native/codex/:sessionID/queue` 下的排队、删除和继续操作；账户额度为 `GET /native/codex/usage`。追加输入沿用原生交付账本记录送达证据；待发队列保存在服务端数据目录 `native-queue/<projectID>/<sessionID>.json`，原子写入并在执行服务重启后暂停。定向回归覆盖同 ID 重试、陈旧回合拒绝、模式切换、停止后不续发、队列恢复及缺失用量，不替代真实安装版本的交互验收。

回退预检为 `POST /native/codex/:sessionID/revert/prepare`，按返回的操作 ID 调用 `POST /native/codex/:sessionID/revert`；`GET /native/codex/:sessionID/revert` 恢复未决状态。服务端在发送原生回退前原子保存操作记录，之后同 ID 请求只核对已执行结果。原生成功后才裁剪本地消息和交付记录，移除已删除轮次的答案状态与统计；实际文件保持不变。
