# 会话分支与独立 Fork

Aether 支持两种 Fork 方式：保留在当前对话树中，或从选定历史创建独立会话。两种方式沿用相同的消息复制和输入框恢复流程。

## 默认方式

通用设置中的“新 Fork 默认独立”默认关闭。开启后，消息菜单、`/fork` 和回退保护弹窗中的 Fork 都直接创建独立会话。这个设置保存在当前客户端，对该客户端的各项目生效；切换设置仅影响之后的 Fork，不会调整已有会话。关闭对话树显示也可以使用此设置。

独立会话包含 Fork 点之前的继承历史，树图使用现有画法显示这条完整路径。此后关闭默认独立设置，仍可在该会话中继续创建树内分支。

## 手动拆分已有分支

打开需要拆分的子会话，在会话标题的“更多”菜单选择“拆为独立会话”。拆分会带走该会话现有的整棵子树：`A → B → C` 中拆出 B 后，侧栏成为独立的 A 和 `B → C` 两组，C 继续归属 B。

拆分保留会话 ID、消息、标题、草稿、阅读位置和归档状态。侧栏展开新的独立条目；原树与新树分别管理。删除或归档 A 不影响拆出的 B 和 C。新组内部仍按原有规则处理归档、删除及共享历史的回退保护。

待拆子树中的会话或子代理正在生成、重试、等待审批或等待用户回答时，需要先完成或停止相应任务，再进行拆分。子代理没有单独拆分入口。

本阶段不提供合回原树的操作。拆分解除的是结构关系，原分叉锚点不会另外保存为可恢复的关系。

## API 与持久化

- `POST /session/:sessionID/fork` 增加可选的 `detached` 布尔参数；省略或设为 `false` 时，保持树内 Fork 行为。
- `POST /session/:sessionID/detach` 将指定分支及其后代拆成独立树，返回拆分后的根会话。对已经独立的根重复调用保持幂等。
- 默认独立是客户端偏好；直接调用 SDK 或其他客户端时，是否独立由本次 Fork 请求决定。
- 继续使用现有会话字段。手动拆分为整组分配新的 `treeID`，清除根的对外父级与 Fork 锚点，保留子树内部关系，无需迁移已有数据。
- 项目库整体提交结构变化后，通过现有会话更新事件刷新客户端。旧请求不得根据拆分前的关系重新挂接分支。
